---
title: Connect an MCP client
description: Connect Claude.ai, Mistral, Cursor, or any MCP client to your tenant's MCP server so AI assistants can search and read your Nextcloud content.
---

Your tenant runs a hosted **MCP server**, so any
[Model Context Protocol](https://modelcontextprotocol.io) client can search and
read your knowledge bank on your behalf. Connecting from Nextcloud isn't
required — semantic search in the unified search bar works without any external
client — but an MCP client lets assistants like Claude or Mistral act on your
content.

## What you need

- Your tenant's **MCP server URL** (the same tenant URI from
  [setup](/getting-started/setup), e.g.
  `https://<your-tenant>.mcp.astrolabecloud.com`).
- An MCP client that supports **remote** (HTTP) MCP servers.

<Callout title="First connection signs you in">

The first time a client connects, it runs an OAuth login against **your**
Nextcloud. You approve access once; the client then searches and reads your
content as you, scoped to what background sync has indexed.

</Callout>

## Claude.ai / Claude Desktop

1. Open **Settings → Connectors** (Claude.ai) and choose **Add custom
   connector** — or, in Claude Desktop, **Settings → Connectors → Add**.
2. Enter your tenant's **MCP server URL** as the remote server URL and save.
3. Complete the sign-in prompt to authorize access to your Nextcloud.
4. In a chat, enable the connector and ask about your content.

## Mistral (Le Chat)

Le Chat does not register itself dynamically, so its OIDC client has to be
created by hand in your Nextcloud and then allowed on your tenant.

<Callout title="Do these in order — finish step 3 before you open the Mistral console">

Your tenant's MCP server rejects any client id that isn't on its allowlist, so
the connector cannot work until step 3 is done. Allowing a client also has to
reach the running MCP server, which takes a few minutes and is not finished the
moment the portal saves the change.

If you add the connector too early, the first authorization attempt is rejected
with an unknown-client error — and **retrying from the Mistral console does not
recover it** once the allowlist is correct. Delete the connector and add it
again.

</Callout>

<Steps>

<Step n="01" title="Create a confidential OIDC client in Nextcloud">

Go to **Settings → Administration → OpenID Connect Provider** and add a client:

- **Type:** Confidential
- **Redirection URI:** `https://callback.mistral.ai/v1/integrations_auth/oauth2_callback`

The client now has a **Client ID** and a **Client secret**. Both stay
readable on the client's detail panel, so you can come back for them at any
time.

</Step>

<Step n="02" title="Set the client's allowed scopes">

On the same client, fill in **Allowed Scopes** with a space-separated list:
the four standard OIDC scopes plus one scope per capability you want Mistral to
have.

```
openid profile email offline_access semantic.read notes.read files.read calendar.read
```

`semantic.read` gates `nc_semantic_search` — without it the connector can read
individual items but can't search your knowledge bank, which is usually the
whole point.

Leaving the field empty allows **all** scopes — fine for a trusted admin
client, but prefer listing only what the connector needs.

Available application scopes:

| Area | Scopes |
| --- | --- |
| Semantic search | `semantic.read` |
| Notes | `notes.read`, `notes.write` |
| Files (incl. WebDAV) | `files.read`, `files.write` |
| Calendar | `calendar.read`, `calendar.write` |
| Tasks | `todo.read`, `todo.write` |
| Contacts | `contacts.read`, `contacts.write` |
| Deck | `deck.read`, `deck.write` |
| Tables | `tables.read`, `tables.write` |
| Collectives | `collectives.read`, `collectives.write` |
| Cookbook | `cookbook.read`, `cookbook.write` |
| Talk | `talk.read`, `talk.write` |
| Sharing | `sharing.write` |
| News | `news.read` |
| Mail | `mail.read`, `mail.send` |

Tools whose scope isn't granted simply don't appear to the client, so a
read-only scope set is a safe starting point.

</Step>

<Step n="03" title="Allow the client on your tenant">

In the Astrolabe Cloud portal, open your tenant and find **MCP clients →
Add MCP client**:

- **Client ID:** the id from step 1
- **Friendly name:** e.g. `Mistral Le Chat`
- **Redirect URI:** `https://callback.mistral.ai/v1/integrations_auth/oauth2_callback`

Your tenant's MCP server rejects client ids that aren't on this list, so this
step is required — the redirect URI must match the one registered in Nextcloud.

</Step>

<Step n="04" title="Add the connector in the Mistral console">

This is an admin task in the Mistral console, not something you do from a Le
Chat conversation. Go to [console.mistral.ai](https://console.mistral.ai) →
**Connectors** → **+ Add Connector** → **Custom MCP Connector**, and supply:

- your tenant's **MCP server URL**
- the **Client ID** and **Client secret** from step 1

Authorize access when prompted. The connector is then available to enable in
Le Chat conversations.

</Step>

</Steps>

## Cursor and other clients

Clients that use a JSON config (Cursor's `mcp.json`, and similar) point at the
same remote URL, for example:

```json
{
  "mcpServers": {
    "astrolabe": {
      "url": "https://<your-tenant>.mcp.astrolabecloud.com"
    }
  }
}
```

The client opens the authorization flow on first use.

<Callout title="Third-party UIs change">

The exact menu names and steps in Claude, Mistral, and Cursor change over time.
If a label here doesn't match, look for wherever the client adds a **remote /
custom MCP server** and supply your tenant's MCP server URL.

</Callout>
