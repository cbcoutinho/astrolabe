---
title: Set up Astrolabe Cloud
description: Install the apps, register two OIDC clients, create your tenant (with billing), point Astrolabe at your Cloud backend, and set the clients' redirect URIs.
---

This guide connects your self-hosted Nextcloud to the managed Astrolabe Cloud
backend. When you're done, you'll move on to
[indexing your content](/getting-started/indexing).

## Setup steps

<Steps>

<Step n="01" title="Install the apps and register two OIDC clients">

In your Nextcloud, open **Apps**, find **Astrolabe**, and choose **Download and
enable**. Also enable the **OpenID Connect** provider app (`oidc`) — Astrolabe
uses it to mint short-lived, per-user tokens, so no separate identity provider
is required.

<Screenshot
  label="The Astrolabe app in Nextcloud's App Store with the Enable button in the app detail panel."
  src="/astrolabe-install.png"
  width={342}
  height={470}
/>

Then go to **Settings → Administration → OpenID Connect Provider** and create
**two** clients:

- **Astrolabe frontend — public client.** This client's id is your
  **management client id**. It lets the Cloud MCP server trust requests coming
  from the Astrolabe UI.
- **Astrolabe Cloud — confidential client.** Nextcloud generates a **Client
  ID** and **Client secret**. Astrolabe Cloud uses these to provision your
  tenant and mint per-user tokens server-side. Both stay readable on the
  client's detail panel, so you can come back for them later.

<Callout title="Redirect URIs: use a placeholder for now">

Nextcloud asks for a **Redirect URI** on each client, but the real values only
exist once your tenant is live. Enter the temporary placeholder
`https://placeholder.invalid/callback` on both clients now — `.invalid` is
reserved and never resolves — and replace it in step 5.

</Callout>

<Callout title="Which id goes where?">

The **management (public) client id** is used in two places: the Cloud
tenant-creation form (step 2) and your Nextcloud admin page (step 4). The
**confidential** client's id **and secret** are only entered in the Cloud
tenant-creation form.

</Callout>

<Screenshot
  label="Nextcloud's OpenID Connect Provider admin showing the registered clients, including the public Astrolabe frontend client and the confidential Astrolabe Cloud client."
  src="/oidc-clients.png"
  width={1100}
  height={509}
  caption="At this step your list shows only the two clients you just created — the other entries here come from additional MCP integrations added later."
/>

</Step>

<Step n="02" title="Create your tenant in Astrolabe Cloud">

In the Astrolabe Cloud portal, open **New tenant**. The form has two sections:

**Tenant identity** — a **Display name**, a **Slug** (lowercase letters,
numbers and hyphens, 3–40 chars — it becomes your tenant subdomain), a
**Contact email**, a **Plan**, and an **Embedding provider**.

<Callout title="The embedding choice is permanent">

The **Embedding provider** (API — Mistral, or in-process) sizes the vector
index at provisioning and **can't be changed afterwards without a destructive
re-provision**. Pick deliberately.

</Callout>

**Connect your Nextcloud** —

- **Nextcloud URL** and **OIDC issuer URL** (usually the same Nextcloud base
  URL; it must serve `/.well-known/openid-configuration`).
- the **confidential** client's **OIDC client ID** and **OIDC client secret**
  (so Cloud can provision your tenant and authenticate to your Nextcloud).
- under **Management API (optional)**, put the **management (public)** client
  id in **Allowed management clients** (so the MCP server trusts your Astrolabe
  UI). Leave it empty to keep that API closed.

Cloud validates OIDC discovery against your issuer before it lets you continue.

<Screenshot
  label="Astrolabe Cloud tenant-creation form: tenant identity (name, slug, plan, embedding provider) and the Connect-your-Nextcloud fields (URL, issuer, confidential client id + secret, allowed management clients)."
  src="/cloud-tenant-form.png"
  width={1425}
  height={1925}
/>

</Step>

<Step n="03" title="Set up billing">

Continue to checkout — Astrolabe Cloud redirects you to **Stripe** to set up
your subscription. Once payment is confirmed, your tenant is queued for
provisioning.

<Screenshot
  label="Stripe checkout page for the Astrolabe Cloud subscription."
  src="/stripe-checkout.png"
  width={1440}
  height={900}
  caption="Shown in Stripe's test (“Sandbox”) mode; the production checkout is identical without the Sandbox badge."
/>

</Step>

<Step n="04" title="Point Astrolabe at your tenant">

When provisioning finishes you'll receive a **tenant-ready email** with your
**tenant URI** and the two **redirect URIs** you'll need in step 5. The tenant
URI is also the **Public URL** shown on the tenant page, of the form
`https://<your-slug>.tenants.astrolabecloud.com`. Back in Nextcloud, open
**Settings → Administration → Astrolabe** and fill in:

- **MCP Server URL (internal)** — your **tenant URI**. Must be `https://`.
- **MCP Server URL (public)** — leave blank to reuse the internal URL, or set
  it explicitly; it becomes the audience (`aud`) of the minted access tokens.
- **OIDC client identifier** — your **management (public) client id** from
  step 1.

Save, and the **service-status** panel should report the backend as reachable
and healthy.

<Callout title="Field naming">

The app has two URL fields — **“MCP Server URL (internal)”** (where Astrolabe
reaches the MCP server) and **“MCP Server URL (public)”** (the token audience).
For a Cloud tenant, put your tenant URI in the internal field; the public field
can be left blank. The management client id goes in **“OIDC client
identifier”**.

</Callout>

  src="/astrolabe-admin.png"

  height={708}
  caption="When it's connected, the service-status panel reports the backend reachable with Auth Mode: oauth."
/>

</Step>

<Step n="05" title="Update the redirect URIs">

Now that the tenant is live, replace the placeholder redirect URIs from step 1.
In Nextcloud, open **Settings → Administration → OpenID Connect Provider**,
edit each client, and set its **Redirect URI** to the value from your
tenant-ready email — or, if your email doesn't list them, build them from the
table below:

| Client | Redirect URI |
| --- | --- |
| **Astrolabe Cloud — confidential client** | `https://<your-slug>.tenants.astrolabecloud.com/oauth/callback` |
| **Astrolabe frontend — public client** | `https://<your-nextcloud>/apps/astrolabe/oauth/callback` |

- The **confidential** client's URI is the MCP server's OAuth callback on your
  tenant: your **tenant URI** followed by `/oauth/callback`, with no trailing
  slash.
- The **public** client's URI is on your own Nextcloud: the **Nextcloud URL**
  you entered in step 2 (including any subpath, but no trailing slash),
  followed by `/apps/astrolabe/oauth/callback`.

Redirect URIs are matched exactly, so copy them rather than retyping them.
Remove the `https://placeholder.invalid/callback` placeholder afterwards so it's no longer
an accepted redirect target.

</Step>

</Steps>
